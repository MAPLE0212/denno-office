# 電脳オフィス 6席（ミニキャラ版）実装ドキュメント

M5Stack StopWatch の円形画面（466×466）に、オフィスの島（6席）をミニキャラで表示するファームウェアの実装メモ。
主に「島の背景と席の絵をどう焼いて、端末でどう重ねるか」の記録。サーバ連携とキャラごとの絵（`server/sprites/`、`tools/bake_chara.py`）は README を参照。

---

## 1. 全体像

```
[PC] Three.js でシーンを組む (tools/bake6.html)
   │  ヘッドレス Chromium で 1 コマずつ描画 (tools/bake6.py)
   ▼
 背景 PNG ＋ 席ごとのキャラ PNG（10 コマ × まばたき有無）＋ 座標 JSON
   │  差分マスク化・RGB565・ランレングス圧縮 (tools/pack6.py)
   ▼
 firmware/office_art.h（画像データを C 配列で埋め込み）
   │  PlatformIO でビルド
   ▼
[StopWatch] firmware/main.cpp が毎フレーム合成して表示
```

- 3D 描画は PC 側で済ませ（プリレンダリング）、マイコンは「画像を重ねるだけ」にしている。
  ESP32-S3 には GPU がなく、ミニキャラの丸みやグロー（Bloom）を実時間で描くのは重すぎるため。
- 見た目を変えるときは Three.js 側を直して焼き直す。ファーム側のコードは基本的に触らない。

## 2. ファイル構成

| パス | 役割 |
|---|---|
| `platformio.ini` | StopWatch 用のビルド設定（公式ドキュメントの `[env:m5stack-stopwatch]` に合わせたもの） |
| `firmware/main.cpp` | 合成・表示・入力処理（手書き） |
| `firmware/denno_config.example.h` | Wi-Fi とサーバの設定のサンプル（`denno_config.h` にコピーして使う） |
| `firmware/office_art.h` | 画像データと席の座標（**生成物。手で編集しない**） |
| `tools/bake6.html` | ミニキャラ・机・島の Three.js シーン（焼き付け用ページ） |
| `tools/bake6.py` | bake6.html をヘッドレスで開き、背景と各コマを PNG に書き出す |
| `tools/pack6.py` | PNG 群を office_art.h に変換し、合成プレビューも出力 |
| `tools/bake_chara.py` / `bake_chara.html` | 選んだキャラを6席分の差分スプライト（`server/sprites/`）に焼く（サーバが自動で呼ぶ） |
| `docs/stopwatch-preview.png` | 実機で出る想定の画面（全員在席・コメントあり） |

## 3. ハードウェアと前提

- M5Stack StopWatch（SKU C152）：ESP32-S3R8、Flash 16MB、PSRAM 8MB、1.75" 円形 AMOLED 466×466（CO5300 / QSPI）、タッチ、ボタン×2
- ライブラリ：M5Unified / M5GFX / M5PM1 / M5IOE1（GitHub 最新を参照）
- 画面は円形なので、四隅（円の外）は表示されない。描画要素はすべて円の内側に置く。

## 4. 画面の構成

視点は写真と同じく「島の手前左から斜めに見下ろす」固定カメラ。

| 席 | インデックス | 列 | 備考 |
|---|---|---|---|
| A1〜A3 | 0〜2 | 手前（背中が見える） | 吹き出しは椅子の下に出す |
| B1〜B3 | 3〜5 | 奥（顔が見える） | 吹き出しは頭の上に出す |

表示要素：

- **キャラ**：在席の席だけ描く。全員タイピングのループ（10コマ）。席ごとに開始コマをずらして同期して見えないようにしている（`(frameIdx + i*3) % FRAMES`）。
- **まばたき**：B列（顔が見える3人）のみ。2〜6秒おきにランダムで 2 フレーム目を閉じる。A列は後ろ向きなのでまばたき版を持たず、通常コマを流用。
- **不在タグ**：不在の席の椅子の上に「名前 不在」を描く。
- **吹き出し**：在席かつコメントありのときだけ。上段に「席コード 名前」、下段にコメント。幅 100px 固定で、はみ出す文字はクリップ。
- **操作中表示**：画面下端に「操作中 A1 佐藤」。

## 5. 描画パイプライン（main.cpp）

起動時：

1. 466×466・16bit の `M5Canvas` を PSRAM に 2 枚確保（`canvas` = 合成用、`bgc` = 背景保持用）。各 約434KB。
2. 背景 JPEG（`BG_JPG`、約57KB）を `bgc` に一度だけデコード。

毎フレーム（`TICK_MS = 80ms`、約12fps）：

1. `bgc` → `canvas` を `memcpy`（背景で塗り直し）
2. キャラを **奥の列 → 手前の列** の順（`DRAW_ORDER = {3,4,5,0,1,2}`）に `blit()` で上書き
3. 不在タグ → 吹き出し → 操作中表示を描く
4. `canvas.pushSprite(0,0)` で画面へ転送

奥から順に塗ることで、手前の人が奥の人に重なる前後関係が正しく出る（画家のアルゴリズム）。
家具（机・モニター）は背景に焼き込んであるため、キャラと家具の前後関係は焼き付け時点のものになる（後述の制約参照）。

### スプライト形式（`blit()` が読むデータ）

各コマは「背景と違うピクセルだけ」を持つマスク付きのランレングス形式。`uint16_t` の並び：

```
各行ごとに:
  nRuns
  nRuns 回繰り返し: skip, len, pixel[len]
```

- `skip`：直前のランの終わりからの空きピクセル数、`len`：塗るピクセル数
- `pixel` は **バイトスワップ済み RGB565**（LovyanGFX のスプライトバッファの並びに合わせ、`memcpy` で直接書けるようにしている）
- 座標は席ごとの矩形 `SEATS[i].x, y, w, h` 基準（全コマの差分の和集合で決めた矩形）

`SeatArt` 構造体（office_art.h）：

```cpp
struct SeatArt {
  int16_t x, y, w, h;            // スプライト矩形（画面座標）
  const uint16_t* open[FRAMES];  // 通常コマ
  const uint16_t* blink[FRAMES]; // まばたきコマ（A列は open と同じ）
  int16_t headX, headY;          // 頭上の点（吹き出し配置の参考）
  int16_t chairX, chairY;        // 椅子の上の点（不在タグの位置）
};
```

### データ量の目安（現行の焼き付け結果）

| 項目 | サイズ |
|---|---|
| キャラスプライト合計（6席・10コマ・B列まばたき込み） | 約1.06MB |
| 背景 JPEG | 約57KB |
| PSRAM 使用（キャンバス2枚） | 約0.87MB / 8MB |

Flash のアプリ領域（default_16MB パーティション）に十分収まる。

## 6. 入力と状態

```cpp
struct SeatState { code, name, present, comment, presetIdx, nextBlink, blinkLeft };
```

| 入力 | 動作 |
|---|---|
| 画面タップ | タップ位置を含むスプライト矩形（±10px）のうち中心に最も近い席の在席を反転し、その席を選択 |
| BtnA | 操作対象の席を次へ |
| BtnB | 操作対象の席のコメントを定型文で順送り（なし／集中モード／寒い…／暑い…／午後から会議／話しかけOK） |
| シリアル 115200 | `p <席>` 在席反転、`c <席> <文>` コメント設定、`c <席>` コメント消去（席は 0〜5） |

名前・初期コメントは `S[6]` にサンプルとしてハードコードしている。

## 7. 吹き出しの配置

吹き出しは自動配置ではなく、席ごとの決め打ち（`BUB[6]`：箱の中心x・上端y・しっぽ先端の座標）。
円の内側に収まり、互いに重ならない位置を `preview.png` で確認しながら決めた。

- 視点や島の配置を変えて焼き直した場合、**`BUB` の値も手で調整し直す必要がある**。
  目安として `office_art.h` の `headX/headY`（頭上）と `chairX/chairY`（椅子）を使う。

## 8. 見た目を変えて焼き直す手順

### 環境

```bash
cd tools
npm install                       # three@0.160.0
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium
```

### 変更できる場所

| 変えたいもの | 場所 |
|---|---|
| キャラの形・顔・髪 | `bake6.html` の `makeChara()`（B2 だけは `makeCharaC02()`） |
| 席ごとの色違い・キャラ差し替え | `bake6.html` の `VARIANTS`（髪・ジャケット・シャツ・パンツ・リボン色。`make` で組み立て関数、`O` で輪郭色も差し替えられる） |
| 座りポーズ・タイピングの動き | `bake6.html` の `bakePose()` |
| 机・椅子・島の配置 | `bake6.html` の「island of 6 seats」部分（`DESK_W`, `Z0` など） |
| カメラ（視点・画角） | `bake6.py` の `CAM` |
| コマ数 | `bake6.py` の `N` |
| 差分判定のしきい値 | `pack6.py` の `THR` |

### 実行

```bash
python3 bake6.py --test   # 全員そろった1枚だけ出して構図を確認 → bake6_out/test_all.png
python3 bake6.py          # 本番の焼き付け → bake6_out/
python3 pack6.py          # ../firmware/office_art.h と bake6_out/composite_preview.png を生成
```

その後 PlatformIO でビルド・書き込み。視点を変えた場合は 7 章の `BUB` も合わせて直す。

### 席のキャラを焼き込みの段階で置き換える

（マイページで選んだキャラを実機に出すだけなら、サーバと `bake_chara.py` が自動でやるのでこの手順は不要。ここはサーバにつながないときの既定の絵を変えたい場合）

ミニキャラは `characters/cXX.html` に1体ずつある。どれも bake6.html と同じ部品（`part` / `joint` / `capsule` / `toon` / `rampSoft` / `outlineMat`）で組んであるので、キャラを組み立てる関数をそのまま移植できる。
例として、2026-10-19 に B2 を c02 に置き換えている（`bake6.html` の `C02` / `O02` / `makeCharaC02()`）。

1. **cXX.html から3つをコピーする**
   - `const C = { ... }`（体の色）
   - `const O = { ... }`（輪郭の発光色）
   - `function makeChara() { ... }`（キャラの組み立て）
2. **bake6.html に貼って名前を変える**：`makeCharaC02()` の後に貼り、`C` → `C0X`、`O` → `O0X`、`makeChara` → `makeCharaC0X` にする。
   - 関数の**中身**は `C.hair` や `O.hair` のまま変えない。`makeCharaWith()` が組み立ての間だけ、グローバルの `C` / `O` を席の色に差し替える。
   - cXX.html にしかない補助関数や定数を使っていたら、それも一緒に移す。
3. **関節の名前をそろえる**：`bakePose()` と `__bake.shot()` が使うので、返す `J` に次がすべて必要。
   `root, hips, thighL/R, kneeL/R, chest, shL/R, elL/R, neck, head, eyes, braidL/R`
   おさげがないキャラは、c02 の末尾と同じく空の `joint` を `braidL/R` に入れておく。
4. **席を差し替える**：`VARIANTS` の該当行を次の形にする（席の並びは A1, A2, A3, B1, B2, B3 = 0〜5）。
   ```js
   { make: makeCharaC0X, O: O0X, ...C0X },   // B2: characters/c0X
   ```
   `make` を省くと `makeChara()`（標準のおさげキャラ）で組み、色だけ変わる。
5. **焼き直す**：上の「実行」の3コマンド。まず `--test` の `test_all.png` で、差し替えた席に新しいキャラがいるかを見る。
6. **確認する**
   - `pack6.py` の出力の `seat N [x, y, w, h]` で、差し替えた席だけ矩形が変わっているか（他の席は変わらないはず）。
   - `bake6_out/composite_preview.png`（全員在席の合成）で見た目を確認する。
   - 髪型で頭の高さが大きく変わったら、吹き出しが頭に重ならないか確認し、必要なら 7 章の `BUB` を直す（`office_art.h` の `headX/headY` が目安）。
   - B列（3〜5）は顔が見えるのでまばたきコマも焼かれる。目が前髪に隠れていないかも見る。
7. **書き込む**：PlatformIO は VS Code 拡張と一緒に入っていて PATH が通っていないことがある。`pio` が見つからなければフルパスで実行する。
   ```bash
   ~/.platformio/penv/bin/pio run -t upload
   ```

元に戻すときは、`VARIANTS` の該当行を色の指定（例：`{ hair: 0x1e1e3c, blazer: 0x3a6bd0, shirt: 0xc9b8ff }` が元の B2）に戻して焼き直す。
初期状態で不在の席（`main.cpp` の `S[]` で `present` が `false`）は、起動直後は「不在」タグだけが出る。タップして在席にするとキャラが表示される。

## 9. 設計上の判断と理由

| 判断 | 理由 |
|---|---|
| 端末上で 3D を描かない | ミニキャラの曲面・トゥーン陰影・Bloom はソフトウェア描画では重く、見た目も劣化する |
| 席ごとの差分スプライト | 背景と違う部分だけ持てば容量が小さく、重なりも描画順で正しく扱える |
| JPEG でなく RLE+RGB565 | 毎フレームのデコードが不要で、`memcpy` だけで速く描ける。透過（マスク）も表現できる |
| 全画面をキャンバスで合成してから転送 | ちらつきが出ず、重なり部分の描き直し漏れも起きない |
| 吹き出し位置は決め打ち | 6席・固定視点なので自動レイアウトより確実。円形画面の端に寄るのも避けやすい |

## 10. 既知の制約

- **家具との前後関係が固定**：机・モニターは背景に焼き込んでいるため、キャラは常に家具より手前に描かれる。
  現在の視点では、手前列の椅子の背もたれがキャラに隠れるべき箇所でも隠れない。必要なら「手前の家具だけの前景レイヤー」を追加で焼き、キャラの後に重ねる。
- **ポーズはタイピングのみ**：待機ポーズや離席アニメはファームに入っていない（1人版のプロトタイプには待機ポーズあり）。
- **焼き込みの絵は B2 以外の5人が色違いのみ**：髪型・服の形は同じ。B2 はミニキャラ c02（`characters/c02.html`）に差し替え済み。サーバにつないだときは、席ごとに選んだキャラの絵に差し替わる。
- **吹き出しは1行・最大幅100px**：長いコメントは切れる。
- **サーバにつながないときは状態が端末内のみ**：在席・コメントは電源を切ると初期値に戻る。
